## 1. บทนำ

### 1.1 วัตถุประสงค์
อธิบายความต้องการเชิงฟังก์ชันและไม่ใช่ฟังก์ชันของเว็บแอป Tokyo Trip Planner ให้ผู้พัฒนาและผู้ทดสอบใช้อ้างอิง

### 1.2 คำศัพท์
| คำ | ความหมาย |
|---|---|
| ทริป (Trip) | ข้อมูลทั้งหมดของทริปเดียว เก็บเป็น JSON ก้อนเดียว (`TripData`) |
| วัน (Day) | หนึ่งวันของทริป มีวันที่, ชื่อวัน, OOTD |
| กิจกรรม (Activity) | รายการในแผนรายวัน มีแผนหลักและแผนสำรองได้หลายแผน |
| แผน (Place) | รายละเอียดของแผนหนึ่ง: ชื่อ, โน้ต, แผนที่, รูป, ไกด์ไลน์, กิจกรรมย่อย, การจอง |
| กิจกรรมย่อย (SubTask) | จุดย่อยในกิจกรรม มีระดับ Must/Nice และติ๊กทำแล้วได้ |
| OOTD | ธีมการแต่งกายของวัน พร้อมรูปตัวอย่าง |
| ค่าใช้จ่ายที่ได้มา (Derived expense) | ค่าใช้จ่ายที่ระบบสร้างจากข้อมูลส่วนอื่น (จอง, เที่ยวบิน, ที่พัก, Wishlist, Checklist) แก้ไขที่ต้นทางเท่านั้น |
| จ่ายส่วนของตัวเองแล้ว (Paid share) | สมาชิกจ่ายคืนคนออกก่อน หรือจ่ายเองแล้ว |
| ผู้ชม (Guest) | โหมดดูอย่างเดียว |

### 1.3 เทคโนโลยี
| ส่วน | เทคโนโลยี |
|---|---|
| Frontend | Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS v4 |
| Backend | Next.js Route Handlers (`/api/trip`, `/api/images`) |
| ฐานข้อมูล | Supabase Postgres — ตาราง `trips` (data JSON + version) |
| เก็บรูป | Supabase Storage — bucket สาธารณะ `trip-images` (สร้างอัตโนมัติ) |
| โฮสต์ | Vercel |

## 2. ภาพรวมระบบ

### 2.1 เมนูหลัก
เมนูแฮมเบอร์เกอร์ทางซ้าย ลากเรียงลำดับได้ (จำต่ออุปกรณ์) และมีตัวเลือกธีมด้านล่าง

| เมนู | หน้าที่ | ส่วนใน SRS |
|---|---|---|
| Trip Planner | แผนรายวัน + แท็บ All (ภาพรวม) | 3.2, 3.3 |
| Reservations | รายการการจองทั้งหมด | 3.4 |
| Wishlist | ของที่อยากซื้อ | 3.7 |
| Budget | ค่าใช้จ่ายและการหารเงิน | 3.6 |
| Travelers | สมาชิก | 3.9 |
| Activity Type | ประเภทกิจกรรม | 3.10 |
| Checklist | ของที่ต้องเตรียม | 3.8 |

### 2.2 ข้อมูลหลัก (`TripData`)
`name`, `members[]`, `categories[]`, `days[]`, `activities[]`, `expenses[]` (เพิ่มเอง), `checklist[]`, `wishlist[]`, `wishTags[]`, `flights[]`, `hotels[]`, `paidShares` (expense id → member ids), `thbPerJpy`

## 3. ความต้องการเชิงฟังก์ชัน

### 3.1 เข้าสู่ระบบและสิทธิ์ (BR-01)
| ID | ความต้องการ |
|---|---|
| FR-AUTH-01 | หน้าเข้าใช้แสดงชื่อทริป, ปีทริป และช่วงวันที่เที่ยว รูปแบบ `09 - 15 Dec 2026` |
| FR-AUTH-02 | ผู้ใช้เลือกโปรไฟล์แล้วใส่ PIN 4 หลัก; สมาชิกที่ยังไม่ตั้ง PIN ใช้ PIN เริ่มต้น |
| FR-AUTH-03 | เก็บเฉพาะ hash ของ PIN (SHA-256 โดยใช้ member id เป็น salt) ไม่เก็บตัวเลขจริง |
| FR-AUTH-04 | ต้องโหลดรายชื่อโปรไฟล์ครบก่อนแสดง ไม่แสดงโปรไฟล์ตัวอย่างชั่วคราว |
| FR-AUTH-05 | โหมดผู้ชม: ซ่อนปุ่มเพิ่ม/แก้/ลบ/ยืนยันทั้งหมด เหลือเฉพาะปุ่มปิด, ดูรายละเอียด, แชร์ |
| FR-AUTH-06 | ระบบจำโปรไฟล์ที่เลือกไว้ต่ออุปกรณ์ จนกว่าจะออกจากระบบหรือหมดเวลา (FR-AUTH-07) |
| FR-AUTH-07 | **Session timeout**: ไม่มีการใช้งาน (แตะ/คลิก/พิมพ์/เลื่อน) เกิน 30 นาที → ออกจากระบบและกลับหน้าเลือกโปรไฟล์ ทั้งสมาชิกและผู้ชม พร้อมข้อความ "ไม่มีการใช้งานเกิน 30 นาที จึงออกจากระบบให้แล้ว"; เวลาใช้งานล่าสุดเก็บใน localStorage ใช้ร่วมกันทุกแท็บ (ใช้แท็บหนึ่งอยู่ แท็บอื่นไม่หลุด); ตรวจทุก 30 วินาที, ตอนกลับมาที่แท็บ และตอนเปิดแอป (ปิดแอปไว้เกิน 30 นาทีต้องเข้าใหม่) |

### 3.2 Trip Planner — แผนรายวัน (BR-02, BR-03)
| ID | ความต้องการ |
|---|---|
| FR-PLAN-01 | แท็บวันแสดงรูปแบบ `WED 09`; หัววันแสดง `WED 9 DEC`; เพิ่ม/แก้/ลบวันได้ |
| FR-PLAN-02 | กิจกรรมจัดกลุ่มตามช่วงเวลา เช้า / บ่าย / เย็น / ค่ำ และเรียงตามเวลา |
| FR-PLAN-03 | กิจกรรมมีแผนหลักและแผนสำรองได้หลายแผน ("แผนหลัก", "แผนสำรอง", "สำรอง N") เลือกแผนที่ใช้งานได้ |
| FR-PLAN-04 | แต่ละแผนมี: ชื่อ, โน้ต, ลิงก์ Google Maps, รูป (สูงสุด 8), ไกด์ไลน์, กิจกรรมย่อย, การจอง |
| FR-PLAN-05 | ลิงก์แผนที่ใช้ข้อความ "Open Map" ทุกจุด และอยู่บรรทัดเดียวกับชื่อ ชิดขวา |
| FR-PLAN-06 | ติ๊ก "ไปแล้ว" → แสดงป้าย "ไปแล้ว" สีเขียวอ่อน และพับรายละเอียดแผนอัตโนมัติ |
| FR-PLAN-07 | กิจกรรมย่อย: มีชื่อ, โน้ต, ลิงก์แผนที่, รูป, ระดับ Must/Nice (สีต่างกัน), ติ๊กทำแล้ว; สรุป Must/Nice ที่เหลือ; พับ/กางได้; ถ้ายังไม่มีแสดงแค่ลิงก์เพิ่มแบบเรียบ |
| FR-PLAN-08 | ถ้ามี Wishlist ที่ยังไม่ซื้อผูกกับกิจกรรม แสดงลิงก์สีแดง "มีของที่ต้องซื้อ" กดแล้วไปหน้า Wishlist ที่กรองกิจกรรมนั้น |
| FR-PLAN-09 | OOTD ต่อวัน: ธีม + รูปตัวอย่าง |
| FR-PLAN-10 | ค่าใช้จ่ายของกิจกรรมแสดงเป็นบาท (ค่าเริ่มต้นสกุลเงินคือ THB) |
| FR-PLAN-11 | **เวลาเดินทางระหว่างกิจกรรม**: ใต้กิจกรรมแต่ละรายการ (ยกเว้นรายการสุดท้ายของวัน) แสดงแถวการเดินทางไปกิจกรรมถัดไปตามลำดับเวลา (1 → 2 → 3 … ข้ามช่วงเช้า/บ่าย/เย็น/ค่ำได้) ใช้ลิงก์ Google Maps ของแผนที่ใช้งานอยู่ แสดงวิธีเดินทาง (เดิน / รถไฟ-รถสาธารณะ), เวลาโดยประมาณ, ระยะทางเส้นตรง และลิงก์ "เส้นทาง ↗" เปิดเส้นทางจริงใน Google Maps |
| FR-PLAN-12 | การประมาณ: ระยะเส้นตรง ≤ 1.2 กม. = เดิน (4.5 กม./ชม.); ไกลกว่านั้น = รถไฟ/รถสาธารณะ (+12 นาทีเดินไปสถานีและรอ, ความเร็วเฉลี่ย 25/40/120 กม./ชม. ตามระยะ); ระยะเส้นทางคิด 1.3 เท่าของเส้นตรง; ปัดเศษ 5 นาทีเมื่อเกิน 10 นาที; ไม่ถึง 100 ม. แสดง "อยู่ใกล้กัน"; ถ้าเวลาเดินทางเกินช่วงห่างของเวลากิจกรรม แสดงคำเตือน |
| FR-PLAN-13 | พิกัดอ่านจากลิงก์ (`!3d…!4d…`, `?q=lat,lng`, `@lat,lng` ฯลฯ); ลิงก์ย่อ `maps.app.goo.gl` และลิงก์ที่มีแค่ชื่อ/ที่อยู่ ให้เซิร์ฟเวอร์หาพิกัดผ่าน `GET /api/geo` แล้วจำผลไว้ในเครื่อง (localStorage); หาไม่เจอแสดง "ยังประมาณเวลาไม่ได้" พร้อมบอกว่ากิจกรรมไหนไม่มีพิกัด แต่ยังกดดูเส้นทางได้ (ใช้ชื่อสถานที่แทน) |
| FR-PLAN-14 | **ลำดับกิจกรรมย่อย** (เก็บต่อแผนใน `subtaskOrder`): ค่าเริ่มต้น "เรียงอัตโนมัติ · ที่ใกล้กันก่อน" — เริ่มจากจุดที่ใกล้หมุดของกิจกรรมหลักที่สุด แล้วไปจุดที่ใกล้ที่สุดถัดไป (nearest-neighbour + 2-opt) จัดใหม่เองเมื่อเพิ่ม/แก้หมุด; กิจกรรมย่อยที่ไม่มีพิกัดอยู่ท้ายตามลำดับที่เพิ่ม; ถ้ากิจกรรมหลักไม่มีพิกัดเลือกเส้นทางรวมที่สั้นที่สุด |
| FR-PLAN-15 | ลากจัดลำดับกิจกรรมย่อยเองได้ (ที่จับ ⋮⋮, กดค้างบนมือถือ, ปุ่ม ↑/↓) → เปลี่ยนเป็น "เรียงเอง" และเก็บลำดับนั้น (เพิ่มใหม่ต่อท้าย); ปุ่ม "รีเซ็ตเป็นลำดับแนะนำ" กลับไปเรียงอัตโนมัติ; โหมดผู้ชมลากไม่ได้ |
| FR-PLAN-16 | ระหว่างกิจกรรมย่อยที่ติดกันซึ่งมีลิงก์แผนที่ทั้งคู่ แสดงวิธีเดินทาง เวลาโดยประมาณ ระยะทาง และลิงก์ "เส้นทาง ↗" แบบเดียวกับ FR-PLAN-11–13 (ไม่มีคำเตือนเวลา เพราะกิจกรรมย่อยไม่มีเวลา) และคำนวณใหม่ทันทีเมื่อลำดับเปลี่ยน |
| FR-PLAN-18 | **ช่องสถานที่บน Google Maps** (กิจกรรมหลัก, แผนสำรอง, กิจกรรมย่อย): พิมพ์ชื่อสถานที่ (≥ 2 ตัวอักษร) แล้วแสดงรายการสถานที่แนะนำ (ชื่อ + ที่อยู่) จาก `GET /api/places` เรียงใกล้จุดอ้างอิงก่อน (กิจกรรมหลัก: ที่พักต้นทางของวัน → กิจกรรมอื่นในวัน → พิกัดใดๆ ที่รู้; กิจกรรมย่อย: หมุดของกิจกรรมหลัก); เลือกด้วยเมาส์/แตะ หรือ ↑/↓ + Enter → บันทึกลิงก์ Google Maps ของสถานที่ (`/maps/place/<ชื่อ>/@lat,lng`) และเติมชื่อกิจกรรมให้ถ้ายังว่าง; วางลิงก์ Google Maps ได้เหมือนเดิม; ข้อความที่ไม่ได้เลือกจากรายการบันทึกเป็นลิงก์ค้นหา Google Maps ของข้อความนั้น; มีลิงก์ "เปิดดูใน Google Maps ↗" |
| FR-PLAN-19 | **Tips Guide**: Tips ของแต่ละแผนแสดงเป็นการ์ดพื้นฟ้าอ่อน หัวข้อ "💡 Tips Guide" พร้อมจำนวนข้อ, แต่ละข้อมีเลขลำดับในวงกลม ตัวอักษรขนาดเล็ก (เท่ากิจกรรมย่อย); กดหัวข้อเพื่อพับ/กางได้แบบเดียวกับกิจกรรมย่อย (ค่าเริ่มต้นกางอยู่ แสดงทุกข้อ) |
| FR-PLAN-17 | **จุดเริ่มต้นของวัน → กิจกรรมแรก**: เหนือกิจกรรมแรกของแต่ละวันแสดงแถวการเดินทาง พร้อมวิธีเดินทาง เวลาโดยประมาณ ระยะทาง และลิงก์ "เส้นทาง ↗" โดยอัตโนมัติ; **วันที่เดินทางถึง**: ถ้ามีเที่ยวบิน (ไม่นับขากลับบ้าน) ที่ลงจอดวันนั้นก่อนหรือตรงเวลากิจกรรมแรก เริ่มจากสนามบินปลายทางของเที่ยวบินนั้น แสดง "🛬 จากสนามบิน <สนามบิน> (ลง HH:MM)" (หลายเที่ยวใช้เที่ยวที่ลงล่าสุด) และเตือนถ้าเวลาเดินทางเกินช่วงตั้งแต่เครื่องลงถึงเวลากิจกรรม; พิกัดสนามบินใช้ลิงก์ Google Maps ของสนามบินปลายทางในเที่ยวบินนั้น ถ้าไม่มีจึงค้นจากรหัส/ชื่อ (เช่น "NRT" → "NRT airport") ผ่าน `GET /api/geo`; **วันอื่น**: "🏨 จากที่พัก <ชื่อ>" — ที่พักของคืนก่อนหน้า (วันเช็กเอาต์นับเป็นจุดเริ่มด้วย) ถ้าไม่มีใช้ที่พักที่เช็กอินวันนั้น; พิกัดจากลิงก์แผนที่ของที่พัก ถ้าไม่มีลิงก์ค้นจากที่อยู่ (หรือชื่อ); ไม่มีทั้งเที่ยวบินและที่พักไม่แสดง |

## 4. Interface ภายนอก

### 4.1 API
| Endpoint | หน้าที่ | สิทธิ์ |
|---|---|---|
| `GET /api/trip` | อ่านข้อมูลทริปและเวอร์ชัน | ทุกคน |
| `PUT /api/trip` | บันทึกข้อมูลทั้งทริป พร้อมเวอร์ชันที่อ้างอิง; ถ้าเวอร์ชันไม่ตรงตอบ conflict พร้อมข้อมูลล่าสุด | ต้องมี `x-trip-member` + `x-trip-pin` (และ `x-trip-prev-pin` ตอนเปลี่ยน PIN) |
| `POST /api/images` | อัปโหลดรูป คืน URL สาธารณะ | ต้องมี header สมาชิก + PIN |
| `GET /api/places?q=&lat=&lng=` | ค้นหาสถานที่ระหว่างพิมพ์ผ่าน Photon (ข้อมูล OpenStreetMap) คืนสูงสุด 6 รายการ `{name,address,lat,lng}`; แคช CDN 1 วัน | ทุกคน |
| `GET /api/geo?url=` | หาพิกัดของลิงก์ Google Maps: ตามการ redirect ของลิงก์ย่อ (เฉพาะโดเมน Google Maps) แล้วถ้ายังไม่มีพิกัดค้นจากชื่อ/ที่อยู่ในลิงก์ผ่าน Nominatim; คืน `{lat,lng}` หรือ `null`; แคช CDN 30 วัน | ทุกคน |

### 4.2 บริการภายนอก
- Supabase (Postgres + Storage)
- Google Maps (ลิงก์เปิดภายนอก และอ่านพิกัดจากลิงก์/การ redirect ของลิงก์ย่อ; ไม่ใช้ API key)
- OpenStreetMap Nominatim (หาพิกัดจากชื่อสถานที่เมื่อลิงก์ไม่มีพิกัด; จำกัด 1 ครั้ง/วินาที ต่อเซิร์ฟเวอร์)
- Photon by Komoot (ค้นหาสถานที่ระหว่างพิมพ์จากข้อมูล OpenStreetMap; ไม่ใช้ Google Places API จึงไม่ต้องมี API key)
- โลโก้สายการบินจากบริการรูปโลโก้ตามรหัส IATA (ถ้าโหลดไม่ได้แสดงรหัสแทน)
- เมนูแชร์ของระบบปฏิบัติการ (Web Share API) สำหรับส่งรูปไป LINE
